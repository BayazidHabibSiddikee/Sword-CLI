Objective

•  To interface a 4×4 matrix keypad with ATmega32 microcontroller.
•  To display the pressed key on an LCD (16×2).
•  To understand scanning techniques of matrix keypads.
•  To use Arduino as ISP (In-System Programmer) for burning code into ATmega32

Required Equipment’s:

•  Arduino UNO, ATmega32
•  LCD Display, 1k ohm resistance, jumpers
•  Keypad
•  Tools: avr-gcc, avr-objcopy, avr-dude or Arduino IDE

Introduction:
Embedded  systems  have  become  a  cornerstone  of  modern  electronics,  enabling  intelligent
control  and  automation  in  everyday  devices.  The  ATmega32  microcontroller,  a  member  of
Atmel's  popular  AVR  family,  is  one  of  the  most  widely  adopted  8-bit  microcontrollers  in
educational and professional embedded system design. With its 32 KB of flash memory, built-
in analog-to-digital converter, hardware timers, and support for serial communication protocols
such as SPI and USART, the ATmega32 provides a compact yet capable platform for a wide
range of applications.

Fig 1: Controlling LCD with the help of 4x4 Keypad Matrix

A matrix keypad is an input device consisting of rows and columns arranged in a grid. A 4×4
keypad  has  16  keys,  connected  using  8  pins  instead  of  16,  which  reduces  pin  usage  in
microcontrollers.  When  a  key  is  pressed,  it  connects  a  specific  row  and  column.  The
microcontroller scans the rows and columns to detect which key is pressed. A 16×2 LCD is
used to display characters. It works in either 8-bit or 4-bit mode; 4-bit mode is commonly used
to save pins. The ATmega32 microcontroller reads keypad input and sends corresponding data
to the LCD. Since ATmega32 does not have a built-in USB programmer, an Arduino board is
used as an ISP burner to upload the program.

main.c:

#define F_CPU 8000000UL
#include <avr/io.h>
#include <util/delay.h>
#include "lcd.h"
// Keypad connections
#define ROW_PORT PORTA
#define ROW_DDR  DDRA
#define ROW_PIN  PINA
#define COL_PORT PORTB
#define COL_DDR  DDRB
#define COL_PIN  PINB

char keypad[4][4] = {
    {'1','2','3','A'},
    {'4','5','6','B'},
    {'7','8','9','C'},
    {'*','0','#','D'}
};
void keypad_init() {
    ROW_DDR = 0x0F;     // Lower 4 bits output (rows)
    ROW_PORT = 0xF0;    // Enable pull-up for columns
    COL_DDR = 0x00;     // Columns input
    COL_PORT = 0xFF;    // Pull-up enabled
}
char keypad_getkey() {
    for (int row = 0; row < 4; row++) {
        ROW_PORT = ~(1 << row);   // Activate one row
        for (int col = 0; col < 4; col++) {
            if (!(COL_PIN & (1 << col))) {
                _delay_ms(50);   // Debounce
                while (!(COL_PIN & (1 << col))); // Wait release
                return keypad[row][col];
            }
        }
    }
    return 0;
}
int main(void) {
    lcd_init();
    keypad_init();
    lcd_string("Press Key:");
    while (1) {
        char key = keypad_getkey();
        if (key) {
            lcd_cmd(0xC0);   // Move to second line
            lcd_data(key);
        }
    }
}

Lcd.h

void lcd_command(unsigned char cmd){
    LCD_PORT = (LCD_PORT & 0x87) | (cmd & 0xF0);   // High nibble
    LCD_PORT &= ~(1<<LCD_RS);     // RS = 0 for command
    LCD_PORT |= (1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT &= ~(1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT = (LCD_PORT & 0x87) | ((cmd << 4) & 0xF0);  // Low nibble
    LCD_PORT |= (1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT &= ~(1<<LCD_EN);
    _delay_ms(1);
}
void lcd_data(unsigned char data){

    LCD_PORT = (LCD_PORT & 0x87) | (data & 0xF0);   // High nibble
    LCD_PORT |= (1<<LCD_RS);      // RS = 1 for data
    LCD_PORT |= (1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT &= ~(1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT = (LCD_PORT & 0x87) | ((data << 4) & 0xF0); // Low nibble
    LCD_PORT |= (1<<LCD_EN);
    _delay_ms(1);
    LCD_PORT &= ~(1<<LCD_EN);
    _delay_ms(1);
}
void lcd_init(void){
    LCD_DDR = 0xFF;               // All LCD pins as output
    _delay_ms(20);
    lcd_command(0x02);            // 4-bit mode
    lcd_command(0x28);            // 2 line, 5x8 font
    lcd_command(0x0C);            // Display on, cursor off
    lcd_command(0x06);            // Auto increment
    lcd_command(0x01);            // Clear screen
    _delay_ms(2);
}
void lcd_string(const char *str){
    while(*str) lcd_data(*str++);
}
void lcd_clear(void){
    lcd_command(0x01);
    _delay_ms(2);
}
void lcd_set_cursor(uint8_t row, uint8_t col){
    uint8_t address = (row == 0) ? 0x80 : 0xC0;
    lcd_command(address + col);
}

Discussion:
The keypad works using a row-column scanning method. The microcontroller sets one row low
at a time and reads column inputs. If a key is pressed, the corresponding column becomes low,
allowing detection of the pressed key. The LCD receives commands and data through the lcd.h

library, simplifying control operations such as initialization, cursor positioning, and character
display.  Using  Arduino  as  a  burner  (ISP)  eliminates  the  need  for  a  dedicated  programmer,
making the system cost-effective and flexible. Challenges faced may include: Key debounce
issues, Incorrect wiring of rows and columns , Timing mismatch in LCD initialization

Conclusion:
The experiment successfully demonstrated how to interface a 4×4 keypad with ATmega32 and
display  inputs  on  an  LCD.  It  enhanced  understanding  of  input  scanning  techniques,  LCD
interfacing,  and  microcontroller programming  using Arduino  as  ISP.  The project  reinforces
several important concepts in embedded systems engineering, including GPIO configuration,
peripheral  interfacing,  keypad  matrix  scanning,  interrupt  or  polling-based  sensor  reading,
software debouncing, and real-time display output using segment lookup tables. The modular
firmware design allows for straightforward modification and extension of the system.
In conclusion, this project serves as a well-rounded example of embedded system design that
combines hardware interfacing, firmware logic, and practical utility. It demonstrates that even
a  modest  32-bit  microcontroller,  when  properly  programmed  and  interfaced,  is  capable  of
implementing responsive and reliable multi-input control systems.
