Introduction:
Embedded  systems  have  become  a  cornerstone  of  modern  electronics,  enabling  intelligent
control  and  automation  in  everyday  devices.  The  ATmega8  microcontroller,  a  member  of
Atmel's  popular  AVR  family,  is  one  of  the  most  widely  adopted  8-bit  microcontrollers  in
educational and professional embedded system design. With its 8 KB of flash memory, built-
in analog-to-digital converter, hardware timers, and support for serial communication protocols
such as SPI and USART, the ATmega8 provides a compact yet capable platform for a wide
range of applications.

Fig 1: Controlling LED’s with the help of IR sensor’s output

ATmega8: The ATmega8 serves as the central processing unit of this system. Operating at up
to 1 MHz with it’s internal oscillator, it executes the firmware that governs all input reading,
logic processing, and output driving. The microcontroller's General Purpose I/O (GPIO) pins
are  configured  appropriately:  some  as  inputs  (for  the  IR  sensor  signal  and  keypad

rows/columns) and others as outputs (for the 7-segment display segments). The ATmega8's
internal pull-up resistors are utilized on keypad input lines to avoid floating states, ensuring
reliable key detection.

Programming is performed using an Arduino Uno configured as an ISP. The Arduino IDE's
ArduinoISP sketch is uploaded to the Uno, and the SPI lines (MOSI, MISO, SCK) along with
the  RESET  line  are  connected  to  the  corresponding  pins  on  the  ATmega8.  This  method  is
reliable, cost-effective, and particularly suitable for educational and prototyping environments.

7 Segment LED display:
The  7-segment  display  is  a  common-cathode  type,  consisting  of  seven  individual  LED
segments (labeled a through g) and one decimal point segment. Each segment is connected to
a dedicated output pin of the ATmega8 through a current-limiting resistor. By driving specific
combinations of these segments HIGH, the microcontroller can display any digit from 0 to 9.
A  lookup  table  in  the  firmware  maps  each  digit  to  its  corresponding  8-bit  segment  pattern,
enabling efficient and fast display updates.
In the default off state, all segment outputs are driven LOW, keeping the display blank. This
conserves  power  and  clearly  indicates  to  the  user  that  the  system  is  idle  and  awaiting  a
command.
4x4 Keypad Matrix:
The 4×4 matrix keypad provides manual input to the system. It consists of 16 keys arranged in
a 4-row by 4-column matrix. The ATmega8 scans the keypad by sequentially driving each row
LOW while reading the column inputs. When a key is pressed, it creates a short circuit between
a row  and a  column, allowing the firmware to  identify the specific key  by the row-column
combination. The keypad is used for three distinct purposes in this system:
Keys 0–9: Pressing any numeric key immediately displays the corresponding digit on the 7-
segment display. The display updates in real time upon each key press, functioning essentially
as a direct digit output mode.
Key 'C' (Count): Pressing 'C' activates the automatic counting mode, in which the IR sensor
controls the displayed count. Each object detected by the IR sensor causes the digit on the 7-
segment display to increment by one.
Key 'A' (All Reset): Pressing 'A' resets the entire system. The count variable is cleared to zero,
the display is turned off, and the system returns to its default idle state, ready to accept new
commands.
IR Sensor:
The IR sensor module consists of an IR LED emitter and a photodiode receiver, along with
onboard comparator circuitry that produces a clean digital output signal. When an object passes

within the detection range, the reflected infrared light triggers the receiver, and the module's
output transitions from HIGH to LOW (active low output). The ATmega8's firmware detects
this falling edge through interrupt-driven or polling-based detection and increments the internal
count variable accordingly.

Fig 5: IR Sensor
To  prevent  false  triggering  due  to  multiple  detections  from  a  single  object  pass  (known  as
bouncing  or  chattering),  a  software  debounce  delay  is  implemented  in  the  firmware.  This
ensures  that  each  physical  object  passing  the  sensor  is  counted  exactly  once,  maintaining
accuracy of the counter.

System Operating Modes and Logic Flow
The system operates across three distinct modes governed by the keypad input and the current
system state:
Idle/Off Mode: This is the default state after power-on or after pressing 'A'. The 7-segment
display remains blank. The IR sensor is inactive (ignored by firmware). The system waits for
a keypad input.
Manual Digit Mode: Triggered when any key from 0 to 9 is pressed. The corresponding digit
is immediately displayed on the 7-segment display. No IR sensor counting occurs in this mode.
IR Counting Mode: Activated by pressing 'C'. The display begins at the current count (or zero
after a reset). Each object detected by the IR sensor increments the displayed count. This mode
continues until 'A' is pressed to reset the system.

During testing, the system performed reliably across all three operating modes. Digit display
on  key  press  was  immediate  with  no  visible  lag.  The  IR  sensor  counting  mode  accurately
detected  objects  passing  within  its  detection  range,  with  the  debounce  implementation
preventing double-counting. The reset function using key 'A' consistently cleared the display
and returned the system to the idle state without requiring a power cycle.
One observed limitation was that the display is a single-digit 7-segment unit, limiting the count
range to 0–9 before rolling over or stopping. An extension of this project could incorporate a
multi-digit display or a multiplexed display driver to support higher counts.

Conclusion:
This  project  successfully  demonstrates  the  implementation  of  a  multi-mode  counter  system
using the ATmega8 microcontroller, a 7-segment LED display, an IR sensor, and a 4×4 matrix
keypad.  The  system  achieves  its  intended  functionality  across  all  three  operating  modes:
idle/off  state,  manual  digit  display  via  keypad,  and  automatic  object  counting  using  the  IR
sensor. The use of an Arduino Uno as an In-System Programmer proved to be a practical and
cost-effective approach for programming the ATmega8 without requiring dedicated hardware.
The project reinforces several important concepts in embedded systems engineering, including
GPIO configuration, peripheral interfacing, keypad matrix scanning, interrupt or polling-based
sensor  reading,  software  debouncing,  and  real-time  display  output  using  segment  lookup
tables. The modular firmware design allows for straightforward modification and extension of
the system.
In conclusion, this project serves as a well-rounded example of embedded system design that
combines hardware interfacing, firmware logic, and practical utility. It demonstrates that even
a  modest  8-bit  microcontroller,  when  properly  programmed  and  interfaced,  is  capable  of
implementing responsive and reliable multi-input control systems.
