**Theory:**

A binary counter is a hardware circuit that is made out of a series of flip-flops. The output of one flip-flop is sent to the input of the next flip-flop in the series. A binary counter can be either asynchronous or synchronous, depending on how the flip-flops are connected together [1].

![Binary Counter in Digital Electronics](data:image/jpeg;base64...)

*Figure- 3.1: Binary Counter* [2]*.*

B**inary counter** is a digital electronic device that counts, stores, and displays the number of times a specific event has occurred. It is a type of sequential logic circuit. To perform the counting operation, it uses a clock signal. In simple words, a binary counter is an electronic device used in digital systems for counter purposes. Overall, the main purpose of this counter is to count and record the number of an occurrence of a particular input signal. A binary counter can perform counting in a specific range, i.e. 0 to (2n – 1), where, 0 is the first count, while (2n – 1) is the last count limit. The variable `n` represents the total number of bits that the counter can handle.

For example, a 8-bit binary counter has n = 8, and therefore it can count between 0000 0000 (0) and 1111 1111 (255) and then come back to the initial stage, i.e. 0000 0000(0) [3].

In this project, an Up-Down Binary Counter is implemented using the Atmega32 microcontroller. The Atmega32 is a popular 8-bit microcontroller from the AVR family, known for its versatility and ease of use. The counter counts up or down based on the state of two push buttons connected to PD2 and PD3 pins of the microcontroller.

**Working Principle:**

1. The data direction register (DDRC) is set to configure PORTC as an output port, while the data direction register for PORTD is configured to set PD2 and PD3 as input pins.

**![](data:image/png;base64...)**

*Figure- 3.2(a): Inactive phase of LEDs in simulation*

1. Pull-up resistors are activated for these input pins to ensure a defined logic level when the switches are open.

**![](data:image/png;base64...)**

*Figure- 3.2(b): Binary Counter circuit active LED (D1 on)*

1. The program entered a continuous loop where it constantly checked the status of the input pins PD2 and PD3. Upon detecting a low signal on PD2, a debounce delay of 10 milliseconds is applied to filter out switch bouncing.

**![](data:image/png;base64...)**

*Figure- 3.2(c): Binary Counter circuit active (D1, D2, D3, D4 on)*

1. If PD2 remained low after the delay, the count is incremented if it is less than 255, and the program waits until PD2 returns to a high logic level.
2. Similarly, when a low signal is detected on PD3, a debounce delay of 250 milliseconds is applied.

**![](data:image/png;base64...)**

*Figure- 3.2(d): Binary Counter circuit active (D1, D2, D3, D4, D5, D6, D7, D7, D8 on)*

1. If PD3 remained low after the delay, the count is decremented if it is greater than 0, and the program waits until PD3 returns to a high logic level. The current count value is then displayed on PORTC, and a delay of 250 milliseconds is applied before the process repeats.

**Code:**

#include <avr/io.h>

#include <util/delay.h>

#define F\_CPU 8000000UL

int main(void) {

DDRC = 0xFF;

DDRD &= ~(1 << PD2);

DDRD &= ~(1 << PD3);

PORTD |= (1 << PD2) | (1 << PD3);

uint8\_t count = 0;

while (1) {

if (!(PIND & (1 << PD2))) {

\_delay\_ms(10);

if (!(PIND & (1 << PD2))) {

if (count < 255) {

count++;

}

while (!(PIND & (1 << PD2)));

}

}

if (!(PIND & (1 << PD3))) {

\_delay\_ms(10);

if (!(PIND & (1 << PD3))) {

if (count > 0) {

count--;

}

while (!(PIND & (1 << PD3)));

}

}

PORTC = count;

\_delay\_ms(100);

}

return 0;

}
