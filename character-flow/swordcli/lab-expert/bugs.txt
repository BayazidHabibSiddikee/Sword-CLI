  Full Bug & Problem Report for LabGen

  🔴 CRITICAL BUGS (will cause crashes / silent failures)

  1. LangGraph draft_report node doesn't receive circuit_json — data flows are broken

  In graph.py, research and circuit both start from START in parallel, but draft_report only depends
  on research. The circuit node writes to circuit_json but goes straight to END without feeding into
  draft_report. So report_sections is generated without any circuit context, and circuit_json in the
  final result comes only from the state—but the state merge behavior in LangGraph may clobber it. The
  draft node never sees circuit data.

  2. run_generation re-generates the netlist from scratch, ignoring graph_result's circuit_json

  In main.py::run_generation, after calling run_pipeline(), the code extracts circuit_json =
  graph_result.get("circuit_json", {}) but then immediately overwrites it by re-building
  netlist_content from that same circuit_json—which may be empty {} if the graph's circuit node result
  didn't merge properly. There is no fallback check: if circuit_json is {}, the resulting netlist is
  just a header line with no components.

  3. execute_dynamic_circuit function is defined but never called

  main.py defines execute_dynamic_circuit() which does proper LLM circuit generation + schemdraw
  execution, but run_generation duplicates all its logic inline instead of calling it. The function is
  dead code.

  4. _build_data_table_from_simulation uses wrong column indices

  df = pd.read_csv(txt_out, sep=r'\s+', header=None)
  if df.shape[1] >= 4:
      v = pd.concat([df[0], df[2]])  # correct for 4-col ngspice wrdata
  else:
      v = df[0]
      i = df[1]

  But the wrdata output from ngspice writes index V I index V I ... format with alternating index
  columns. The actual values are in columns [0,1,2,3] = [idx, V, idx, I]. So df[0] is actually the row
  index and df[1] is V, df[2] is another index, df[3] is I. The column assignments are wrong—the table
  will contain index numbers instead of voltages/currents.

  5. API key is committed in plaintext in settings.json

  settings.json contains "api_key": "sk-nry-TeauyPpk2F3OHFaHuZunwEJaj6j_cJbftoPCMITEc_4". This is a
  live third-party API key hardcoded in a tracked file.

  6. settings.json is not in .gitignore

  The .gitignore likely doesn't exclude settings.json, meaning the exposed API key would be committed
  to git history.

  7. ngspice simulation loop overwrites dynamic.cir on every iteration

  In run_generation, each resistor-value iteration writes to the same cir_path (always dynamic.cir).
  The last write "wins." When ngspice runs asynchronously or there's a race, the CIR used by ngspice
  may not match the intended iteration.

  8. _build_data_table_from_simulation fallback path for _tran.txt is wrong

  if not os.path.exists(txt_out) and os.path.exists(txt_out.replace('.txt', '_tran.txt')):
      txt_out = txt_out.replace('.txt', '_tran.txt')

  But by this point txt_out is iv_data.txt. The transient files were written as iv_data_0_tran.txt,
  iv_data_1_tran.txt etc., not iv_data_tran.txt. So the fallback never matches and the function
  returns an empty string—causing the "No parsable data table" verification failure seen in the actual
  runs.

  9. LaTeX regex substitutions in server.py::run_generation_with_progress are broken

  body = re.sub(r"\section\*?\{([^}]+)\}", r"## \n", body)
  body = re.sub(r"\textbf\{([^}]+)\}", r"****", body)
  body = re.sub(r"\textit\{([^}]+)\}", r"**", body)

  The capture group \1 is never used in the replacement strings—all section titles and bold/italic
  text are dropped. The markdown preview in the UI will be completely empty headings and missing
  formatted text.

  10. verify_report API endpoint is a stub that always returns passed: true

  @app.post("/api/verify")
  async def verify_report(request: VerifyRequest):
      return {"status": "verified", "summary": {"passed": True, "failures": 0, "warnings": 0}}

  16. ingest.py::_guess_sections references re without importing it at module top

  re is imported only at the bottom of ingest.py (used by extract_pdf via the import re inside
  extract_pdf's scope—actually it's a top-level import missing). Actually import re from pipeline.ocr

  NameError: name 're' is not defined when _guess_sections runs.

  17. circuit_templates.py buck-boost template has a broken ngspice netlist

  The fallback netlist:

  "L1 2 0 100u",
  "D1 3 2 D1N4148",
  "C1 3 0 470u",
  "Rload 3 0 10",
  ".model D1N4148 D(...)"

  V1 connects nodes 1→0 but L1 connects 2→0, with nothing connecting node 1 to node 2 (no switch/PWM
  transistor). The circuit is open and ngspice will either error or produce trivial results. This is
  the main "working" fallback circuit and it's wrong.

  This outputs literal \n characters as two characters (\ + n) in the context string instead of real

  20. cad.py::execute_and_validate appends duplicate import cadquery as cq inside generated script

  21. verify.py::run_all_checks dispatches validators with a fragile chained if hasattr on the same
  line

  issues.extend(validator.check_text(report) if hasattr(validator, "check_text") else
                validator.check_data(report) if hasattr(validator, "check_data") else ...)

  If a validator has multiple check_* methods (which none currently do, but it's extremely fragile),
  only the first matching method runs. Also, semantics uses check_semantics not
  check_text/data/structure/circuit/references, so the chain falls through correctly—but this will
  silently skip any new validator that doesn't follow the exact naming convention.

  training/prediction and adds several seconds of HTTP latency. During training on 200+ PDFs this

  23. The _tran.txt column mapping in the transient plot is wrong

  In run_generation:

  df_tran = pd.read_csv(loop_txt_out.replace('.txt', '_tran.txt'), sep=r'\s+', header=None)
  tran_data.append((r_val, colors[r_idx % len(colors)], df_tran))
  # Later:
  plt.plot(df_tran[0] * 1000, df_tran[1], ...)

  Again assuming df_tran[0] = time and df_tran[1] = voltage. But ngspice wrdata with two signals
  outputs 4 columns: [idx, val1, idx, val2]. So time is df_tran[1] (col 1) and V(2) is df_tran[3]. The
  transient plot X axis will be row indices × 1000, not time in ms.
